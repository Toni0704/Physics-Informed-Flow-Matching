# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Research code for **Physics-Constrained Flow Matching (PCFM)** — a method for enforcing hard physical
constraints (PDE residuals, initial/boundary conditions, conservation laws) during sampling from
flow-matching generative models. Companion code to the NeurIPS 2025 paper (arXiv:2506.04171). Portions
are derived from `amazon-science/ECI-sampling` (Apache-2.0); the rest is MIT (see `LICENSE`,
`LICENSE-APACHE-2.0`, `NOTICE`).

There is no test suite, linter config, or CI in this repo. There is nothing to "build" — everything
runs as plain Python scripts against local configs/checkpoints.

## Environment setup

Conda envs are defined in `pcfm_env.yml` (Linux/CUDA, pinned/frozen) and `pcfm_env_macos.yml`
(macOS, loose pins — use this one on Apple Silicon). Both create an env named `pcfm`.

```bash
conda env create -f pcfm_env_macos.yml   # macOS
conda env create -f pcfm_env.yml         # Linux/CUDA
conda activate pcfm
```

All commands below assume the repo root is on `PYTHONPATH` / you invoke them from the repo root, since
scripts import via absolute package paths like `from models import get_flow_model` and
`from pcfm import Residuals2D, FFM_NS_sampler`.

## Core architecture (PCFM library)

The two top-level pieces are decoupled: `models/` + `datasets/` train an unconstrained flow-matching
surrogate; `pcfm/` applies physics constraints at sampling time on top of a trained model. Most
experiment scripts wire these two together.

- **`pcfm/`** — the constrained-sampling library, independent of any specific PDE model:
  - `constraints.py` — `Residuals` (1D: IC, mass conservation for heat/reaction-diffusion) and
    `Residuals2D` (2D Navier-Stokes) residual functions used as the constraint set during projection.
  - `pcfm_sampling.py` — the actual constrained-sampling machinery: `pcfm_batched` /
    `pcfm_2d_batched` project flow-matching samples onto the constraint manifold via Newton
    steps/least-squares using `compute_jacobian` and `fast_project_batched(_chunk)`; `make_grid`
    builds the spatial/temporal grid the residuals are evaluated on.
  - `ffm_sampler.py` — `FFM_sampler` / `FFM_NS_sampler`, the flow-matching ODE samplers (vanilla,
    unconstrained) that PCFM projection is layered on top of.
  - Import everything from the package root: `from pcfm import Residuals2D, FFM_NS_sampler, ...`
    (see `pcfm/__init__.py` for the full exported surface).

- **`models/`** — the flow-matching surrogate models being sampled from:
  - `_base.py` — a name-based registry (`register_model` / `get_model`); model `type` strings in
    YAML configs (e.g. `fno`) resolve through this to a class.
  - `fno.py` — Fourier Neural Operator encoder/backbone.
  - `functional.py` (`FFM`) — the flow-matching model wrapper trained by `scripts/training/main.py`.
  - `functional_module.py` (`FunctionalModule`) — PyTorch Lightning wrapper around the same model,
    used by `main_lightning.py`.
  - `ns_model_film_ic.py` — FiLM-IC-conditioned model specific to the 2D Navier-Stokes experiments.
  - Build a model from config via `models.get_flow_model(model_cfg, encoder_cfg)`, never by
    instantiating a model class directly — the encoder/backbone type is data-driven from YAML.

- **`datasets/`** — one module per PDE system (`diffusion.py` for heat, `rd1d.py`, `burgers1d.py`,
  `ns.py`), all exposed through `datasets.get_dataset(config.datasets)` which dispatches on
  `config.datasets.type`. Pre-generated Navier-Stokes trajectories live in `datasets/data/*.h5`
  (generated by `datasets/generate_ns_2d.py`); other PDE datasets are generated on the fly.

- **`configs/`** — one YAML per experiment (`heat.yml`, `rd1d.yml`, `burgers1d.yml`,
  `ns_lightning.yml`). Loaded via `scripts.training.utils.load_config`, which returns an
  attribute-access config object (`config.train.lr`, `config.datasets.type`, etc.) — read an
  existing config file before adding new fields, since the loader doesn't validate a schema.

## Running things

Train the unconstrained flow-matching surrogate (custom training loop, single GPU/CPU):

```bash
python scripts/training/main.py configs/heat.yml --savename my_run --device cuda
```

Train via PyTorch Lightning (multi-GPU):

```bash
python scripts/training/main_lightning.py configs/ns_lightning.yml --savename my_run --devices 4
```

Run constrained sampling / evaluation against a trained checkpoint (this is what actually exercises
the PCFM projection machinery end-to-end — see `scripts/training/run_pcfm_hpc.py` for the reference
usage of `pcfm.Residuals2D` / `pcfm.FFM_NS_sampler`):

```bash
python scripts/training/run_pcfm_hpc.py \
  --config configs/ns_lightning.yml --ckpt logs/my_run/latest.pt \
  --data datasets/data/ns_nw10_nf100_s64_t50_mu0.001.h5 --outdir runs/my_eval
```

`scripts/training/run_pcfm_hpc_multi.py` is a multi-sample/batched variant of the same evaluation.
`scripts/training/ns2d_conditioned.py` is currently fully commented out — treat it as inactive/WIP,
not a working entry point.

## Simple_pendulum/ — independent toy ablations

`Simple_pendulum/` is a self-contained set of experiments applying the same physics-constraint ideas
to a toy pendulum system, entirely separate from the `pcfm`/`models`/`datasets` library above (no
shared imports). Each subdirectory is one ablation arm with its own `config.py`, `data.py`, `model.py`,
`train.py`, `eval.py`, `main.py`, plus its own `checkpoints/` and `outputs/`:

- `Pendulum_data_only` — data-only baseline, no physics constraint.
- `Pendulum_training_constraint` / `Pendulum_inference_constraint` — physics enforced during training
  vs. at inference/sampling time.
- `Pendulum_conditional_H` / `Pendulum_conditional_IC` — conditioning on energy (Hamiltonian) vs.
  initial conditions.
- `Pendulum_2` — later/extended variants (A/B/C) building on the above, run via `--variant {A,B,C}`.

There are no `__init__.py` files, but each `main.py` imports its siblings via the full dotted path
(e.g. `from Simple_pendulum.Pendulum_2.config import ...`), so run these as modules from the repo root:

```bash
python -m Simple_pendulum.Pendulum_2.main --variant C
python -m Simple_pendulum.Pendulum_data_only.main
```

Do not add a `Simple_pendulum/__init__.py` or per-experiment `__init__.py` as a "fix" for import
errors — the modules already resolve correctly as namespace packages when run with `-m` from repo
root; if imports fail it's almost always a wrong invocation directory, not a missing `__init__.py`.

Note: these directories previously lived at the repo root (`Pendulum_2/`, `Pendulum_data_only/`, etc.)
and were moved under `Simple_pendulum/` without an accompanying commit — `git status` on a fresh
checkout may show the old top-level paths as deleted even though nothing was lost.

## Other things worth knowing

- `bratu/` has restrictive permissions (`drwx------`) and is unrelated scratch/experiment space —
  don't assume it follows the same conventions as the rest of the repo.
- `.gitignore` excludes `datasets/`, `logs/`, `checkpoints/`, and model artifacts (`*.pt`, `*.pth`,
  `*.ckpt`, `*.h5`) — large data/checkpoint files under those paths are intentionally untracked, not
  missing.
- `assets/pcfm_figure.png` is the paper's summary figure referenced from `README.md`.
